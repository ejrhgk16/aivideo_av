# plan-39-recommendation-sequential-video

## 목표
추천 화면의 스크롤을 유지하고 긴 스와이프·휠 입력에도 한 입력당 이전 또는 다음 작품 한 개까지만 이동한다. 드래그 중에는 현재 영상이 계속 재생되며, 다음 작품으로 이동이 완료됐을 때만 재생 대상을 전환한다. 준비된 영상에는 표지가 끼어들지 않게 한다.

## 범위와 승인
- 사용자가 스크롤 순차 이동 및 준비된 영상의 표지 생략 범위를 승인했고, 두 파일을 수정하는 단일 task 구성도 승인했다.
- 최종 승인: 스크롤 위치는 화면 이동에 사용하고 재생 대상은 정착 후 확정한다. 이벤트 방향만으로 즉시 작품을 바꾸는 방식은 적용하지 않는다. 작은 드래그 후 복귀하면 기존 영상 재생을 유지한다.
- 중복 이동 방지는 입력·전환 상태로 처리하며 영상 로딩 완료를 기다리지 않는다. 영상 준비 전이나 실패 상태에서도 새 독립 입력으로 다음 작품에 이동할 수 있다.
- 프론트 추천 화면의 이동 이벤트, 영상 표시 조건, 관련 회귀 테스트만 변경한다.
- 이전·현재·다음 영상 사전 로딩 및 플레이어 재사용을 유지한다.
- 로딩 전 검은 배경, 영상 없음·실패 시 기존 표지 대체 표시를 유지한다.
- API·백엔드·DB·다른 화면·디렉터리 책임 변경은 범위 밖이다. 표지 생략만으로 네트워크 또는 디코딩 지연이 사라진다고 가정하지 않는다.

## Task

| 번호 | 이름 | 대상 파일 | 핵심 작업 요약 |
| --- | --- | --- | --- |
| 1 | 추천 순차 이동과 준비된 영상 표시 개선 | `front/src/screens/RecommendationScreen.tsx`, `front/tests/unit/recommendationPreviewBuffer.test.ts` | 한 작품 이동 제한, 드래그 중 현재 영상 재생 유지, 정착 후 재생 전환, 준비된 영상 표지 생략 및 회귀 검증 |
| 2 | 웹 추천 영상 준비 전 VideoView 마운트 | `front/src/screens/RecommendationScreen.tsx`, `front/tests/unit/recommendationPreviewBuffer.test.ts` | 리뷰 P1의 마운트·준비 상태 순환 의존 제거 및 웹 로딩 생명주기 회귀 검증 |

## 실행 순서 및 병렬 작업
- `task-1`은 선행 의존성이 없는 단일 작업이다(`depends_on: []`).
- 두 변경이 동일한 화면 및 기존 테스트 파일을 수정하므로 분할·병렬 실행하지 않는다.
- `task-2`는 `task-1` 완료 후 순차 실행한다(`depends_on: ["task-1"]`). 같은 파일의 구현에 대한 리뷰 후속 수정이다.

## 리뷰 후속 범위
- 사용자가 리뷰 P1만 수정하는 task 작성을 요청했다. 플레이어 준비 전에도 VideoView를 마운트하고 준비 여부는 가시성에만 적용한다.
- 리뷰 P2의 보정 애니메이션 중 새 드래그 처리 및 기존 스크롤·입력 동작은 현재 상태를 유지한다. 입력 차단 기능도 추가하지 않는다.

## 검증
- `npm --prefix front run typecheck`
- `npm --prefix front run test`
- `npm --prefix front run export`
- 구현 시 기존 `http://localhost:8081` 서버의 현재 코드 반영을 확인하고 느린 드래그 중 재생 유지, 원위치 복귀, 정착 후 재생 전환, 긴 입력의 한 작품 이동 및 준비된 영상 표지 생략을 확인한다. 단위 테스트만으로 실제 관성 이벤트나 첫 프레임 표시가 검증됐다고 보고하지 않는다.
- 서버가 없으면 시각적 검증을 실패로 기록하고 `npm --prefix front run start -- --port 8081`을 안내한다. 서버를 자동 실행하거나 다른 포트로 우회하지 않는다.

## 검증 결과
- `task-1`: 타입 검사, 테스트 112개, Expo 내보내기 통과. 실제 브라우저·네이티브 조작은 미검증이다.
- `task-2`: 리뷰 후속 task 작성 완료. 제품 코드 수정 및 추가 검증은 아직 수행하지 않았다.
