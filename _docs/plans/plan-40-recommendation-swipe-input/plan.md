# plan-40-recommendation-swipe-input

## 목표
Swipefeed의 드래그·휠 입력 분리, 관성 중복 방지, 전환 중 입력 잠금 방식을 참고하여 웹과 네이티브 추천 화면의 이동 규칙을 통일한다. 화면 위치를 변경하는 주체를 하나로 만들어 기본 스냅과 추가 보정이 충돌하는 잔움직임을 제거한다. 이동 중 현재 영상 재생, 도착 후 다음 영상 재생을 유지한다.

## 범위와 승인
- 사용자 범위 승인: 웹의 드래그·휠·트랙패드, 네이티브의 터치 드래그·스와이프를 플랫폼에 맞춰 구현하고 한 입력당 한 작품, 전환 중 중복 방지, 도착 후 재생 규칙을 공통 적용한다.
- 사용자 task 구성 승인: 화면과 기존 회귀 테스트 두 파일을 수정하는 단일 task, 선행 의존성 없음.
- Swipefeed 패키지를 추가하지 않고 필요한 동작을 현재 Expo 구조에 맞춰 구현한다. React DOM 전용 컴포넌트를 네이티브에서 사용하지 않는다.
- 손을 놓기 전에는 자유롭게 방향을 바꿀 수 있다. 놓은 뒤 목표가 확정된 애니메이션 중에는 추가 넘김 입력을 무시한다.
- 작은 드래그 복귀 시 재생 위치·일시정지를 보존한다. 준비 전 VideoView 마운트, 준비 후 표지 생략, 인접 플레이어 재사용 및 key 중복 수정은 보존한다.
- 현재 미커밋 상태의 화면·테스트 변경을 기준으로 작업한다. 직전 임시 스냅·보정 처리는 새 입력 흐름이 대체하는 범위에서 제거하되 key 및 웹 영상 마운트 수정은 되돌리지 않는다.
- 백엔드·API·DB·다른 화면·자동 재생 소리 정책·새 의존성·가상화 교체는 범위 밖이다.

## 참고
- [Swipefeed](https://github.com/briansunter/swipefeed): gesture와 wheel을 별도로 처리하고 전환 중 입력을 잠그며 프로그램 이동과 CSS snap의 충돌을 피한다. 참고한 설계와 우리 요구의 차이를 task에 명시한다.
- Swipefeed의 기본 휠 cooldown 800ms나 화면 노출 비율에 따른 즉시 재생을 그대로 복사하지 않는다. 우리 화면은 150ms 입력 종료 판정과 정착 후 재생 전환을 유지한다.

## 실행 순서 및 병렬 작업
- `task-1`은 `depends_on: []`인 단일 작업이다.
- 플랫폼별 입력이 같은 화면의 이동·재생 상태와 테스트를 공유하므로 분할하거나 병렬 실행하지 않는다.
- `task-2`는 `task-1` 완료 후 순차 실행한다(`depends_on: ["task-1"]`). 같은 파일의 입력 영역 정책을 후속 변경하므로 병렬 실행하지 않는다.
- `task-3`은 `task-2` 완료 후 순차 실행한다(`depends_on: ["task-2"]`). 같은 화면과 테스트의 컨트롤 생명주기를 수정하므로 병렬 실행하지 않는다.
- `task-4`는 `task-3` 완료 후 순차 실행한다(`depends_on: ["task-3"]`). 같은 화면과 테스트의 release 판정을 변경하므로 병렬 실행하지 않는다.
- `task-5`는 `task-4` 완료 후 순차 실행한다(`depends_on: ["task-4"]`). 같은 화면과 테스트의 레이아웃 정렬을 수정하므로 병렬 실행하지 않는다.

## 후속 승인
- 사용자가 전환 동작은 정상이나 터치 가능한 영역이 너무 좁다고 보고하고, 재생바만 제외한 추천 피드 전체의 세로 드래그를 허용하는 task 추가를 요청했다.
- 이 요청은 task-1의 버튼 터치 전체 제외 정책을 대체한다. 버튼에서 시작해도 세로 드래그가 인식되면 버튼 동작을 취소하고 작품을 넘긴다. 짧은 탭은 기존 버튼 동작을 수행한다.
- 변경 대상은 추천 피드 내 터치·포인터 드래그다. 휠 처리, 이동 애니메이션 시간·완료 판정, 재생 정책은 유지한다.
- task-3 승인: 사용자가 컨트롤 표시 중 첫 드래그가 컨트롤을 숨기는 것으로 끝난다고 보고했다. 실제 Chrome 터치 입력에서 드래그 grant → scrolling=true → 컨트롤 언마운트 → 이후 touch move/end 단절을 재현했다. 같은 세션에서 컨트롤이 없는 두 번째 드래그는 정상 이동했다.
- task-3은 웹 전용 우회가 아닌 공통 RecommendationScreen의 마운트·가시성 처리를 수정한다. 터치 대상은 제스처 종료까지 유지하고 시각적으로만 숨긴다. 앱에도 같은 코드를 적용하되 네이티브 실제 조작은 별도로 검증한다.
- task-4 승인: 사용자가 짧고 빠른 스와이프 이동을 추가하는 task 작성을 요청했다. 느린 드래그의 절반 기준은 유지하고, 손을 놓기 직전의 빠른 수직 움직임에 별도 이동 조건을 추가한다. 손을 놓기 전에는 목표를 확정하지 않는다.
- 빠른 스와이프 초기값은 최소 이동 50 레이아웃 px, 속도 0.5 레이아웃 px/ms, 마지막 move의 유효 시간 100ms다. 유튜브의 비공개 임계값을 재현한 수치가 아니라 이 화면에서 검증할 초기 설정이다. use-gesture 의존성을 추가하지 않는다.
- task-5 승인: 사용자가 리뷰 P2의 크기 변경 중 정렬 오류를 방지하는 후속 task 작성을 요청했다. 새 카드/콘텐츠 크기가 반영되기 전에 정렬 요청이 기존 스크롤 범위로 제한되는 문제를 해결한다. 마지막 카드에서 화면 높이를 키우는 회귀 검증을 포함한다.

## 검증
- `npm --prefix front run typecheck`
- `npm --prefix front run test`
- `npm --prefix front run export`
- 기존 localhost:8081에서 웹 휠·트랙패드·드래그를 실제 확인하고, 사용 가능한 iOS·Android 환경에서 터치 조작을 확인한다. 실행 환경이 없으면 해당 플랫폼의 조작은 미검증으로 보고한다. export나 모의 이벤트 테스트를 실제 기기 검증으로 표현하지 않는다.
- `task-1`: 타입 검사·테스트 116개·웹/iOS/Android 내보내기 통과. 실제 브라우저·기기 조작은 미검증이며, 이후 사용자가 전환 동작이 정상임을 확인했다.
- `task-2`: 타입 검사·테스트 117개·웹/iOS/Android 내보내기 통과. 이후 실제 Chrome 터치 재현으로 기존 모의 테스트가 포착하지 못한 컨트롤 언마운트 문제를 확인했다.
- `task-3`: 타입 검사·테스트 119개·웹/iOS/Android 내보내기 통과. 실제 Chrome 터치로 컨트롤이 보이는 상태의 첫 드래그와 4.2초 누른 뒤 드래그의 정상 이동 및 터치 대상 유지를 확인했다. 네이티브 기기 조작은 미검증이다.
- `task-4`: 타입 검사·테스트 120개·웹/iOS/Android 내보내기 통과. 실제 Chrome에서 같은 80px 터치 입력의 느린 드래그는 복귀, 빠른 스와이프는 한 작품 이동을 확인했다. 네이티브 실조작은 미검증이다.
- `task-5`: 후속 task 작성 완료. 크기 변경 후 정렬 제품 코드는 아직 수정하지 않았다.
