# 추천 피드 프리뷰 영상 재생

## 목표

`RecommendationScreen.tsx`의 작품별 세로 페이지 스크롤을 유지하면서, 각 작품의 첫 번째 프리뷰 영상을 전체 프레임이 보이도록 재생한다. 재생 중인 카드에 재생·일시정지, 속도, 설정, 탐색 바, 시간 표시, 저장·회차·공유, 작품 상세·첫 회차 진입 조작을 제공한다. 영상이 표시되지 않는 카드에는 포스터 이미지만 보여준다. `playbackScreen_preview.tsx`는 UI 참고 파일로만 사용하고, 추천 화면의 재생 UI는 독립적으로 구현한다.

## 범위와 전제

- 추천 컬렉션의 기존 `previewVideos[0].uuid`를 사용한다. 컬렉션 API 응답에 재생 URL을 추가하지 않고, 첫 표시 작품은 로드 직후, 이후 작품은 스크롤해 활성화될 때 각각 기존 `getPreviewPlayback` API로 URL을 조회한다. 다음 작품 선요청은 측정된 지연이 없어 이번 범위에 포함하지 않는다. 첫 회차 UUID와 가격은 현재 활성 작품에 한해 기존 `getDramaContent`로 조회한다.
- `FlatList`의 세로 `pagingEnabled` 스크롤, 추천 작품 순서와 `initialId` 우선 표시, 추천 탭 화면 구조를 유지한다. 스크롤을 시작하거나 탭을 벗어나면 영상을 멈추고, 화면에 정착한 작품만 재생한다.
- `task-3`에서 기존 포스터 표시를 제거했다. `task-4`에서는 영상 로딩 중, 비활성 카드, 프리뷰가 없거나 재생 URL 조회·영상 재생에 실패한 카드에 포스터 이미지만 표시한다. 이 대체 화면에는 기존 추천 카드의 제목·설명·버튼·배지·그라데이션을 표시하지 않는다. 포스터 URL이 없으면 단색 배경을 사용한다. 일시정지한 영상은 영상 프레임을 유지한다.
- 추천 화면 안에 전용 플레이어와 조작 UI를 구현한다. `playbackScreen_preview.tsx`는 수정하지 않으며 공통 플레이어 컴포넌트도 만들지 않는다. 추천 화면의 저장 상태는 카드 이동 후에도 유지한다.
- 백엔드·API 계약, 회차 재생 화면, 저장 서버 연동, 자막·자동 재생·신고의 실제 기능은 변경하지 않는다. 현재 설정 메뉴의 준비 중 표시를 유지한다.

## 영향 범위

`front/src/screens/RecommendationScreen.tsx`만 변경한다. `_docs/ARCHITECTURE.md`의 디렉터리 책임이나 라우트·API 경로는 바꾸지 않는다.

| 1 | 추천 피드 활성 작품 영상 요청과 재생 | `front/src/screens/RecommendationScreen.tsx` | 첫 카드와 스크롤 후 활성 카드의 재생 URL만 개별 조회하고, 활성 카드에만 영상을 재생한다. |

## 실행 순서 및 병렬 작업

- `task-1`은 선행 작업 없이 실행한다. 다른 작업과 동시에 실행하지 않는다.
- `task-2`는 `task-1` 완료 후 실행한다. 두 작업이 `RecommendationScreen.tsx`를 수정하며, 전체 조작 UI가 활성 카드의 URL·재생 상태를 사용한다.
- `task-3`은 `task-2` 완료 후 실행한다. 동일 화면에서 영상 크기와 포스터 표시를 수정한다.
- `task-4`는 `task-3` 완료 후 실행한다. 기존 재생 카드의 터치·스크롤을 수정하고 영상 대체 화면을 포스터 전용으로 변경한다.

## 검증

- `npm --prefix front run typecheck`
- `npm --prefix front run test`
- `npm --prefix front run export`
- 완료 기준: 추천 탭에서 `initialId` 선택과 세로 페이지 스크롤이 유지되고, 첫 영상 재생 중 연속 스와이프로 다음·이전 작품에 이동한다. 활성 카드만 개별 URL을 요청해 프리뷰 영상의 전체 프레임을 확대·잘림 없이 재생한다. 탭 이탈·스와이프 시 이전 재생이 멈추며 정착한 카드의 영상과 조작 UI가 동작한다. 영상이 표시되지 않는 카드에는 포스터 이미지만 나타나고 기존 카드의 텍스트·조작 UI는 나타나지 않는다. 별도 프리뷰 화면은 수정하지 않는다.
- 위 자동 검증은 화면의 실제 터치·영상 렌더링을 확인하지 못하므로 기기에서 영상의 전체 프레임, 스와이프, 탭 이동, 탐색 바 조작을 수동 확인한다.
