# 07. UI/UX 개선 · 추가 기능 제안

> 현재 시안(`front/`)을 실제 서비스로 만들 때 **고치면 좋은 점**과 **추가하면 좋은 기능**이다. 모두 `[제안]`이며 기획 담당이 채택 여부를 정한다.
> 근거: 현재 코드 분석(GPT-6-Astra), 경쟁 앱·규정 리서치(GPT-6.1-Sol, [부록](./부록_리서치_근거.md)). 기대 효과는 **가설**이며, 출시 후 §5의 지표로 확인한다.

## 3. 추가 기능 제안 (경쟁 앱 벤치마크 기반)

### 3-1. 경쟁 앱에서 확인한 것 (요약)

공식 스토어 소개·약관·FAQ로 확인한 범위다(부록 B). 앱을 설치해 직접 써 본 결과가 아니므로 탭 배치·팝업 세부·광고 횟수처럼 **확인 안 된 것은 사실로 쓰지 않았다.**

| 서비스 | 확인된 특징 | 우리에게 주는 시사점 |
|---|---|---|
| ReelShort | 계정 화면에 Wallet·My List·History, **코인/보너스 잔액 분리**. 공식 안내상 구매 코인은 만료 없음, 무료 보상은 기간 제한이 있을 수 있음(구체 기간은 미확인) | 유상/무상 포인트 분리(03 §4)와 같은 방향 |
| ShortMax | 구매 코인과 보너스 구분, **구매 코인부터 사용**, 배속·다국어 자막·PIP | 차감 순서는 회사마다 다름 → 우리 결정 필요(Q-08) |
| NetShort | 홈 섹션: Trending Now · New Releases · Recommended · Exclusive Originals, **신작 알림**, 찜·시청 기록 | 홈 편성 섹션 구성 참고, 새 회차 알림(P1) |

### 3-3. 직접 확인해 볼 것

공개 자료로는 경쟁 앱의 정확한 하단 탭, 회차 열기 팝업의 세부, 광고 일일 한도, 자동 해제 기본값을 확인할 수 없었다. 출시 전 기획 담당이 **국내 스토어에서 DramaBox·ReelShort·비글루·숏챠를 설치해** 아래를 캡처하면 정책 결정이 쉬워진다.

- 하단 탭 전체와 홈 섹션 구성
- 잔액 충분/부족일 때의 회차 열기 팝업, 자동 해제 설정의 기본값과 끄는 위치
- 광고 1회로 얻는 보상, 하루 한도, 광고가 없을 때 안내
- 첫 구매 할인 표시 방식, 보너스 포인트 유효기간 표시
- 게스트 상태에서 충전 가능 여부, 계정 연동 안내 시점
- 콘텐츠·광고 신고 메뉴 위치

## 4. 출시 전 사용성 테스트 과업

실제 사용자 3~5명에게 아래 과업을 시키고 막히는 곳을 기록한다.

1. 게스트가 무료 마지막 회차 → 잠긴 회차 → 광고 보상 → **직접 열기**까지 성공한다. 보상은 확인 전에 잔액에 보이지 않고, 한 번 연 회차는 다시 차감되지 않는다.
2. 결제 확인 중 앱을 강제 종료 → 다시 열면 기존 거래 상태를 찾아 안내한다. 같은 결제를 다시 요구하지 않는다.
3. 광고를 다 본 뒤 화면을 닫거나 네트워크가 끊겨도 검증된 보상은 들어온다. 덜 봤으면 이유를 알려준다.
4. 추천 피드의 "회차" 버튼·작품 제목·"본편 보기"가 사용자가 예상한 곳으로 간다. 미리보기만 본 것은 시청 기록에 남지 않는다.
5. 한 회차를 끝까지 본 뒤 보관함에 가면 "60초부터 이어보기"가 아니라 다음 화(또는 다시 보기)가 보인다.
6. 작은 화면(320pt)·큰 글자·스크린리더에서 무료 범위·포인트·닫기·다음 화를 찾고 누를 수 있다. 자막과 버튼이 겹치지 않는다.

출시일부터 아래 이벤트를 수집해야 01 문서 §2의 지표를 계산할 수 있다(FN-SVR-06). 분석 도구는 `[TBD]`(제안: Firebase Analytics + 설치 경로 측정 도구 AppsFlyer/Adjust 중 하나).

| `save_toggle` | 찜/찜 해제 | drama_id, saved, from_screen | 찜 → 재방문 |
| `share` | 공유 완료 | drama_id, from_screen | 바이럴 |
| `login_success` | 계정 연동 완료 | provider, trigger(`charge`·`my`·`prompt`) | 연동률 |
| `push_permission_result` | 알림 권한 응답 | granted | 권한 허용률 |

**중복 집계 방지**: `episode_unlock_success`, `ad_reward_granted`, `purchase_success`는 앱이 아니라 **서버가 거래를 처음 확정할 때 1번** 보낸다(거래 ID 포함, 06 §5). 재시도·재조회·재시청으로 다시 보내지 않는다. 앱은 화면 노출·버튼 탭만 보낸다.
**시청 기준**: `episode_complete`(90%)와 랭킹용 "30초 이상 시청"은 진행 막대 위치가 아니라 **실제 재생한 누적 시간**으로 계산한다(건너뛰기 제외).

이벤트에 개인정보(이름·이메일)를 넣지 않는다. 분석·광고 SDK가 수집하는 정보는 개인정보 처리방침과 스토어 개인정보 항목에 반영한다(03 §10).
