# 03. 정책정의서

> 화면과 상관없이 **앱 전체에 똑같이 적용되는 규칙**이다. 개발자는 "이럴 땐 어떻게 하지?"가 생기면 이 문서를 먼저 본다.

> 법·스토어 규정의 출처는 §13에 모았다. 이 문서는 법률 자문이 아니며, 약관·환불 정책은 출시 전 전문가 검토가 필요하다.

## 1. 회원 · 계정

### 1-1. 게스트(비로그인) `[확정: 게스트도 충전 가능, 2026-10-12]`

- 첫 실행에서 공개 약관 조회와 AUT-02의 필수 동의·연령 확인을 끝내면 서버가 **익명 게스트 계정**을 만든다. 이름·이메일 입력이나 소셜 로그인은 요구하지 않는다. 동의 전에는 계정 생성·광고·분석 SDK 실행을 하지 않는다(06 §3-1).
- 게스트도 **무료 시청 · 찜 · 시청 기록 · 광고 보상 · 충전 · 회차 열기**를 모두 할 수 있다 `[확정]`. 충전 직전에는 계정 미연동 경고와 연동 안내를 보여준다(§1-2).
  - 이유(가설): 숏폼 드라마는 "1화 → 무료 구간 → 첫 유료 회차"까지 이탈 없이 가는 게 핵심이고, 첫 유료 회차에서 로그인을 강제하면 전환 마찰이 될 수 있다. 검증된 수치는 없다.
- 게스트 데이터는 서버에 저장되지만, **앱 삭제·기기 변경 시 되찾을 방법이 없다.** 이 위험을 화면에서 안내한다(§1-2).
- 검토했던 대안 B("충전·회차 열기는 로그인 필수")는 채택하지 않았다(Q-02 확정). 게스트 지갑의 복구·병합 처리는 §1-3과 06 §3-10을 따른다.
- **첫 실행 동의·연령 확인** `[확정: 14세 미만도 가입 가능, 콘텐츠 등급에 따라 시청 제한]`: 게스트도 광고·분석 SDK가 동작하기 전에 첫 실행 1회 AUT-02를 거친다 — 필수 약관 동의 + **생년월일 입력**(만 나이 계산). 소셜 로그인 없이 쓰는 게스트도 이 단계를 우회할 수 없다. 광고 보상·충전·회차 열기는 서버도 동의·나이 상태를 확인한다.
- **만 14세 미만** `[제안 · 법률 검토]`: 개인정보 처리에 법정대리인 동의가 필요하다(개인정보 보호법 제22조의2). AUT-04에서 보호자 동의를 받는다.
  - 보호자 동의 전: 무료 시청·찜·시청 기록처럼 서비스 제공에 꼭 필요한 기능만 허용하고, **맞춤형 광고·광고성 알림·충전은 막는다**. 보상형 광고는 비맞춤 광고로만 보여줄지, 동의 전에는 막을지 법률 검토로 정한다 `[TBD]`. 결정 전까지는 **동의 전 보상형 광고도 막는다**(잠정, 2026-10-20 리드 결정).
  - 보호자 동의 후: 일반 이용 가능. 단 콘텐츠 시청은 §3-8의 연령 제한을 따르고, 결제는 미성년자 규칙(§6-4)을 따른다.
- 생년월일은 자기 입력이므로 12·15세 등급 판단에만 쓰고, **청소년관람불가** 작품은 본인인증(AUT-05)으로 만 19세 이상을 확인한 경우에만 보여준다 `[제안]`.

| 항목 | 규칙 |
|---|---|

| 연동 권유 시점 | ① 첫 충전 직전 ② 총 잔액 100P 이상 `[시안]` ③ 내 정보의 "로그인" 버튼. 매번 강제하지 않고 "나중에"로 닫을 수 있다 |
| 권유 문구 | "계정을 연결하면 포인트와 열어 둔 회차를 다른 기기에서도 이어볼 수 있어요." |
| 미연동 경고 | 충전 화면과 로그아웃·데이터 삭제 확인창에 "계정을 연결하지 않으면 앱 삭제·기기 변경 시 포인트를 옮길 수 없어요."를 표시한다. 국내 숏폼 앱 비글루도 같은 경고를 둔다(부록 B13) |

### 1-3. 게스트 → 계정 병합

| 경우 | 처리 |
|---|---|
| 처음 연결하는 계정 | 게스트 계정을 그대로 회원으로 전환(데이터 이동 없음) |
| 이미 데이터가 있는 계정에 로그인 | AUT-03의 명시적 승인 후에만 게스트의 포인트(유상·무상 각각)·열린 회차·찜을 **합친다** `[제안]`. 시청 기록은 §2-5의 서버 순서 기준으로 선택. 합친 뒤 게스트 계정은 비활성화. 원지급 건·원장의 소유자와 출처를 바꾸거나 같은 지급 건을 복사하지 않고, 병합 대상 계정 매핑으로 최종 계정에서 한 번만 사용하게 한다(06 §3-1) |
| 로그아웃 | 새 게스트 상태로 시작(이전 데이터는 계정에 남음). "로그아웃하면 이 기기에서 포인트가 보이지 않아요. 다시 로그인하면 돌아와요." 확인 |
| 병합 "나중에" | 게스트 상태를 유지하고 소셜 연결을 보류한다. 다음 로그인 때 다시 묻는다 `[제안]` |
| 병합 시 금지 | 이미 받은 구매·광고·웰컴 포인트를 다시 지급하지 않는다. 광고 일일 한도는 병합 후 같은 사람 기준으로 이어서 센다. 무상 포인트 유효기간은 새로 시작하지 않는다 |
| 병합 중·이후 도착한 결제·광고 | 원 purchaseIntent·광고 예약에 귀속된 거래를 한 번만 확정한다. 최종 병합 계정을 찾아 잔액에 반영하되 원출처를 보존하고 별도 병합 보상으로 재지급하지 않는다. 병합·동시 소비·콜백을 같은 계정 매핑 기준으로 직렬 처리한다 |

### 1-4. 회원 탈퇴

- 앱 안 **내 정보 → 계정 관리 → 회원 탈퇴**에서 끝까지 진행할 수 있어야 한다(App Store 5.1.1(v), Google Play 계정 삭제 요구). 고객센터 이메일·문의로만 탈퇴하게 하면 심사 거절 사유다.
- **자동으로 만든 게스트 계정도 삭제 대상이다**(Apple 5.1.1(v) 안내). 게스트에게는 "이 기기 데이터 삭제"로 같은 처리를 제공한다.
- Google Play는 앱 안 경로와 별도로 **앱 밖에서 접근 가능한 웹 삭제 요청 페이지 URL**을 Play Console에 등록해야 한다(FN-AUT-07). 계정 비활성화·앱 제거는 삭제로 인정되지 않는다.
- 탈퇴 전 안내: 탈퇴 후 포인트·열린 회차를 앱에서 이용하거나 계정을 복구할 수 없음. 남은 유상·무상 포인트와 확인 중인 결제·광고를 보여주고 환불·정산 문의 경로를 제공한다. 탈퇴가 미사용 유상 포인트의 법적 환불 권리 포기를 뜻한다고 안내하지 않는다 `[TBD: Q-09]`.
- 탈퇴 중·이후에 도착한 유효 결제·광고 보상은 무조건 폐기하지 않는다. 계정을 다시 만들거나 광고·마케팅 SDK를 재활성화하지 않고 **미정산 거래 처리 건(CASE)** 으로 분리해 확정된 환불·정산 정책에 따라 처리한다. 최소한의 거래 연결 자료·연락 방법·처리 기한을 Q-09에서 확정하기 전 실제 결제·광고 기능을 출시하지 않는다(06 §3-1, 01 §6-1).
- 탈퇴 처리: 개인정보는 지체 없이 삭제. 단 법정 보존 기록은 분리 보관 후 기간이 지나면 파기한다 — 계약·청약철회·대금결제·재화 공급 기록 **5년**, 소비자 불만·분쟁 처리 기록 **3년**(전자상거래법 시행령 6조). "탈퇴하면 모든 기록이 즉시 지워진다"고 안내하지 않는다.

## 2. 시청 · 회차

### 2-1. 회차 상태 정의

| 상태 | 뜻 | 회차 칸 표시 | 재생 |
|---|---|---|---|
| `free` 무료 | 작품의 무료 구간(1~N화) 또는 운영자가 개별 무료로 지정한 회차 | "무료" | 바로 재생 |
| `unlocked` 열림 | 사용자가 포인트로 연 회차(또는 운영 지급) | 체크 아이콘 / "열림" | 바로 재생, 추가 차감 없음 |
| `locked` 잠김 | 유료 회차이고 아직 안 엶 | 자물쇠 / "10 P" | 회차 열기 시트 |
| `scheduled` 공개 예정 | 예약 공개 전 | "MM/DD 공개" `[제안]` | 불가 |
| `unavailable` 제공 중단 | 운영자가 숨김 | 표시 안 함 또는 "볼 수 없음" | 불가(§3-3) |

### 2-2. 회차 열기 (포인트 사용) `[확정]`

1. 잠긴 회차를 선택하면 **회차 열기 시트**를 띄운다. 시트에는 `이번 회차 가격 · 내 포인트 · (부족하면) 더 필요한 포인트`를 한눈에 보여준다.
2. 포인트는 **사용자가 "10P로 9화 보기" 버튼을 누를 때만** 차감한다. 시트를 연 것, 광고를 본 것, 충전한 것만으로는 차감·열기를 하지 않는다.
3. 잔액이 부족하면 같은 시트에서 **"광고 보고 포인트 받기"** 와 **"포인트 충전하기"** 를 고르게 한다 `[제안: 웹 시안 방식]`. 광고·충전을 마치면 **같은 회차의 회차 열기 시트로 돌아온다.** 이때 서버에서 최신 가격·잔액을 다시 받아 충분/부족을 다시 판단한다(한 번 받아도 여전히 부족할 수 있음 — 부족분과 남은 광고 기회를 다시 표시). 충분하면 사용자가 보기 버튼을 직접 누른다.
4. 차감·열기는 서버가 한 번에 처리한다(06 문서 §4-1). 같은 회차를 두 번 열려고 해도 한 번만 차감한다(멱등).
5. 처리 중에는 버튼을 비활성화하고 "9화를 준비하고 있어요"를 보여준다. 응답을 못 받으면 실패로 단정하지 않고 "포인트 사용을 확인하고 있어요. 다시 누르지 않아도 돼요."를 보여주며 같은 계정·작업 종류·멱등키의 결과를 조회한다(06 D-9). 최초 거래 결과와 현재 잔액은 구분하며 오래된 성공 응답으로 최신 지갑 상태를 덮어쓰지 않는다. 요청을 보내기 전에 오프라인이면 차감 없이 오류를 안내한다.
6. 가격: **미정 — 출시 마지막 단계에서 확정**한다 `[확정: 2026-10-12]`(시안 10P). 그래서 가격은 **앱 업데이트 없이 어드민에서 언제든 바꿀 수 있어야** 한다: 전체 기본가 / 작품별 기본가 / 회차별 개별가, 즉시 또는 예약 적용, 변경 이력(06 §3-8 `/admin/pricing`). 앱의 모든 가격 문구는 서버 값으로 표시한다(06 D-10). 가격을 바꿔도 이미 연 회차·과거 거래는 영향이 없다.
7. **가격이 바뀐 경우**: 사용자가 시트에서 본 가격과 서버 가격이 다르면 차감하지 않고 "가격이 바뀌었어요. 다시 확인해 주세요."와 새 가격·사용 후 잔액을 보여준 뒤 다시 확인받는다(06 D-8). 사용자가 본 금액보다 많이 차감하는 일은 없어야 한다.

### 2-3. 재생 권한 · 재시청 `[확정]`

- 한 번 연 회차는 **다시 봐도 무료**다. 기기를 바꾸거나 앱을 다시 깔아도 같은 계정이면 유지된다.
- 재생 URL은 서버가 작품·회차 공개 상태와 무료·열림 여부를 확인한 뒤에만 발급한다(04 FN-SVR-02, 06 §3-3). 숨김·공개 예정 회차는 무료·열림이어도 URL을 발급하지 않는다.
- 영상이 재생되지 않아도(네트워크 오류 등) 이미 연 회차는 다시 차감하지 않는다.
- 열린 회차의 시청 가능 기간: **작품이 제공되는 동안** `[제안]`. 작품 제공이 끝날 때의 처리는 §3-3.

### 2-4. 다음 화 자동 재생 · 포인트 자동 사용

| 설정 | 기본값 | 규칙 |
|---|---|---|
| 다음 화 자동 재생 | 켬 `[구현]` | 회차가 끝났을 때 다음 회차가 **무료 또는 열림**이면 바로 재생. **잠김**이면 멈추고 회차 열기 시트를 띄운다 `[구현]` |
| 작품별 포인트 자동 사용 | **꺼짐** `[제안]` | 사용자가 작품별로 켜면, 그 작품의 다음 잠긴 회차를 시트 없이 자동으로 연다. 켤 때 "마지막 신호에서만 적용돼요. 다음 회차부터 회차당 10P를 자동으로 사용해요. 언제든 끌 수 있어요." 확인 후 "이 작품 자동 사용 켜기". 잔액이 부족하면 멈추고 시트를 띄운다. 광고·충전을 자동으로 실행하지 않는다 |

두 설정은 **완전히 별개**다 `[확정]`. 자동 재생을 켰다고 포인트가 자동으로 쓰이지 않는다.

### 2-5. 이어보기 · 시청 기록

- 작품마다 **마지막으로 실제 재생한 회차와 위치(초)** 1개를 저장한다 `[구현]`.
- 저장 시점: 재생 중 10초마다 `[제안]`, 재생 화면을 나갈 때, 앱이 백그라운드로 갈 때. 여러 기기의 순번을 직접 비교하거나 늦게 도착한 요청을 최신 시청으로 간주하지 않는다. 서버가 발급한 재생 세션 순서와 세션 내 증가 순번으로 이전 세션·중복 요청을 제외한다(06 WATCH_PROGRESS·§3-3).
- "이어서 보기"가 갈 곳(resumeTarget)은 실제 시청 기록과 따로 서버가 계산한다 `[제안]`:

| 마지막 상태 | 이어서 보기 대상 |
|---|---|
| 회차 중간에서 멈춤 | 그 회차·위치 |
| 회차를 끝까지 봄 + 다음 회차 무료/열림 | 다음 회차 처음 |
| 회차를 끝까지 봄 + 다음 회차 잠김 | 다음 회차 → 회차 열기 시트(잠긴 회차는 시청 기록에 넣지 않음) |
| 마지막 공개 회차를 봄 + 연재 중 | "다음 화 준비 중"(PLY-08) |
| 완결 작품 마지막 회를 봄 | "처음부터 다시 보기" |

- "끝까지 봄"은 재생이 끝까지 간 것(ended)이다. 분석용 "완주"(90% 시청)와는 따로 계산한다.
- 잠긴 회차, 추천 피드 미리보기는 시청 기록으로 저장하지 않는다 `[구현]`.
- "이어서 보기" 버튼은 기록이 있으면 위 resumeTarget에 따라 회차·위치·대기/완결 행동으로 연결한다 `[제안]`. 기록이 없으면 "N화까지 무료로 보기"/"무료로 시작하기"(1화). 현재 시안은 실제 마지막 회차·위치만 사용한다 `[구현]`.
- 시청 기록 정렬: 최근 본 순. 기록 삭제 기능 `[제안 P1]`.

### 2-6. 추천 피드(미리보기)

- 추천 피드의 영상은 **예고편 또는 1화 일부**로, 운영자가 작품별로 지정한다 `[제안]`. 결말·반전이 담긴 장면은 쓰지 않는다.
- 피드에서 보는 것은 **무료이며 포인트·시청 기록을 바꾸지 않는다** `[구현]`.
- 피드 순서: 운영자 편성 순 `[제안]` → 데이터가 쌓이면 시청 이력 기반 개인화 `[P2]`.
- 첫 진입은 **음소거 자동 재생**, 사용자가 소리를 켜면 피드 안에서 유지 `[제안]`.

### 2-7. 화면·영상 표시

- 세로 9:16 기본. 다른 비율은 원본 비율을 유지하고 여백(검정)을 둔다. 늘리거나 잘라내지 않는다.
- 자막은 회차별 자막 파일로 제공(한국어 기본). 자막이 없는 회차는 자막 설정을 비활성화하고 이유를 표시.

### 2-8. 공유

- 공유하면 **작품 링크**가 전달된다(회차 링크는 `[P1]`). 받은 사람에게 공유한 사람의 포인트·기록은 보이지 않는다 `[구현]`.
- 링크로 들어온 사람에게도 같은 무료·유료 규칙을 적용한다.

## 3. 콘텐츠

### 3-1. 공급 주체 `[확정]`

- 출시 범위: **운영팀 자체 제작(AI DRAMA ORIGINAL)** + **제휴 제작사** 작품. 운영자가 어드민에서 등록·공개한다.
- 개인 창작자 업로드(창작마당)는 출시 범위에서 제외. 확장 시를 대비해 작품에 `studioId`(제작 주체)와 정산용 기록을 처음부터 남긴다.

### 3-2. 무료 범위 · 가격

| 항목 | 규칙 |
|---|---|
| 무료 회차 수 | 작품별 7~10화 `[확정]`. 어드민에서 작품마다 설정 |
| 유료 회차 가격 | 미정 — 출시 마지막 단계에서 확정, 이후에도 어드민에서 변경 가능 `[확정]`(시안 10P, §2-2-6) |
| 무료 범위 표시 | 모든 작품 카드·상세·회차 목록에 "N화까지 무료" 표시 `[구현]` |
| 무료 범위 변경 | 공개 후 무료 범위는 **늘리기만** 허용한다(MVP 단순안 `[제안]`). 무료 회차 수 감소뿐 아니라 이미 공개한 개별 무료 회차의 `freeOverride: true → false`도 거절한다(숨김 후 재공개로 우회 불가). 줄이려면 "이미 무료로 본 회차 보존"을 위한 회차별 무료 이용 기록이 필요하므로 출시 후 별도 설계. 운영자는 특정 회차를 추가 무료로 지정할 수 있다(EPISODE.freeOverride) |

### 3-3. 공개 상태 · 제공 중단

| 상태 | 앱 노출 |
|---|---|
| `draft` 작성 중 / `scheduled` 공개 예정 | 노출 안 함 |
| `published` 공개 중 | 노출 |
| `hidden` 숨김(신고·권리 문제 등) | 목록·검색에서 제외. 이미 연 회차도 재생 불가. 보관함·기록에는 "지금은 볼 수 없어요"로 표시 |
| `ended` 제공 종료 | 신규 시청 불가 |

제공 종료·숨김으로 **포인트로 연 회차를 볼 수 없게 되면** 보상한다 `[제안 · 법률 검토 · TBD(Q-11)]`. 검토할 규칙:

- **일시 숨김**(신고 확인 등, 다시 공개 예정)과 **영구 종료**(권리 종료)를 구분한다. 일시 숨김은 즉시 자동 보상하지 않고 재공개 시 기존 권한을 그대로 살리는 안이다. 장기간 재공개되지 않는 경우의 재검토 시점·환불/보상 처리도 Q-11에서 정한다. 상태를 일시 숨김으로 유지하는 것만으로 이용자의 법적 권리를 배제하지 않는다.
- 영구 종료 시 반환은 원래 거래의 **유상/무상 사용 배분**대로 돌려주는 안을 우선 검토한다(유상으로 쓴 몫을 만료되는 무상으로 바꾸면 사용자 불이익이 될 수 있음). 반환분의 유효기간은 따로 정한다.
- 같은 회차 거래에 같은 사유로 두 번 보상하지 않는다(원래 거래 × 보상 사유 유니크).
- 영향받는 사용자에게 앱 공지·문의 경로를 안내한다.

### 3-4. 홈 편성 · 최신 · NEW

### 3-6. AI 생성 콘텐츠 표시 `[제안]`

근거(2026-10-12 확인): **AI 기본법(2026-01-22 시행) 제31조**는 생성형 AI 기반 제품·서비스 제공 시 AI 운용 사실의 사전 고지, 생성형 AI 결과물 표시, 실제와 구분하기 어려운 가상 영상·음성의 명확한 고지를 요구한다. 예술·창작 표현물은 **감상을 해치지 않는 방식**으로 고지할 수 있다(면제가 아님). 시행령 제23조는 화면·문서 고지, 사람이 인지하거나 기계가 판독하는 표시 방식을 정한다. 우리 회사가 법상 대상 사업자에 해당하는지는 출시 전 법률 검토 `[TBD]`.

| 위치 | 표시 `[제안]` |
|---|---|
| 작품 상세(DTL-01) | 제목 아래 "AI 제작" 배지 + 제작 정보에 "콘텐츠: AI 제작 드라마"(현재 구현 문구 유지) |

- 나이 기준을 섞지 않는다: 개인정보 법정대리인 동의 **만 14세**, 민법상 성년(결제 취소 기준) **19세**, 영상 등급은 작품별.

  - 로그아웃·재설치·게스트 재생성·병합으로 반복 지급되지 않을 인정 기준과 최소 수집 항목을 확정한다(Q-10). **기기 1회**는 검토안이며 단순 설치 ID만으로 재설치를 막을 수 있다고 가정하지 않는다. 판별 수단 승인 전에는 실제 웰컴 지급을 비활성화한다.
  - 무상 포인트로 지급하고 내역에 "가입 축하 포인트"로 남긴다.

### 4-3. 차감 순서 `[확정: 2026-10-12]`

1. 무상 포인트 중 **소멸일이 가까운 것부터**
2. 그다음 유상 포인트

이유: 사용자에게 유리하다(무상 포인트 소멸 손실 최소화, 환불 가능한 유상 포인트 보존). 네이버 시리즈도 무료 이용권(만료 임박순) → 유료 순으로 쓴다. 반대로 ShortMax는 구매 코인을 먼저 쓰므로 업계 공통 규칙은 아니다(부록 B4·B18). 회사 입장에서는 유상 잔액(환불 가능액)이 오래 남는 단점이 있지만, 권장안대로 확정했다(Q-08). 차감 순서는 회차 열기 시트·포인트 화면·유료 서비스 약관에 명시한다.

- 보너스가 붙은 충전 상품을 환불하면 그 상품의 원지급 스냅샷과 잔여 지급 건에 한해 회수한다(구매 전 안내). 이미 사용·소멸·회수한 보너스를 다시 차감하지 않는다. 부족분 처리와 부분 환불 배분은 Q-09 승인 규칙을 따른다.
- 포인트는 현금으로 바꾸거나 다른 사람에게 넘길 수 없다(약관 명시).

## 5. 광고 보상

### 5-1. 지급 조건

| 항목 | 값 |
|---|---|
| 1회 보상 | 10P(무상) `[시안]` |
| 일일 한도 | 5회 `[시안]`. 날짜 기준은 한국 시간 0시 `[제안]` |
| 지급 조건 | 광고를 **끝까지 시청**(광고 네트워크가 보상 완료로 판정) |
| 중간 종료 | 보상 없음. "광고를 끝까지 보지 않아 포인트가 지급되지 않았어요." |
| 광고 없음 | "지금은 볼 수 있는 광고가 없어요. 잠시 후 다시 시도해 주세요." + "포인트 충전하기" |
| 진입 위치 | 회차 열기 시트(잔액 부족 시), 포인트 화면 |

보상량은 **"광고 1회로 회차 1개"**(현재 10P=10P)가 사용자에게 가장 이해하기 쉽다. 광고 단가(eCPM)와 회차 가치를 보고 출시 전 확정 `[TBD]`. 시안의 "하루 5회"는 근거가 있는 값이 아니며, 광고가 없었거나 끝까지 보지 않은 시도는 횟수에 세지 않는다 `[제안]`.

광고 정책상 보상 조건(AdMob 보상형 광고 정책 기준):
- 보상은 **앱 안에서만 쓰는 비현금 재화**여야 한다. 현금·상품권·암호화폐로 바꿀 수 있는 보상으로 확대하지 않는다.
- 광고 전에 조건과 보상량을 보여주고 사용자가 직접 선택해야 한다. 광고를 거절해도 무료 시청 등 기본 이용을 막지 않는다.
- 조건을 채우면 약속한 보상을 반드시 지급한다.

### 5-2. 서버 검증

- 광고 네트워크의 **서버 측 보상 확인(SSV) 콜백**을 받은 뒤에만 지급한다. 앱의 "시청 완료" 신호만으로 지급하지 않는다. 별도 "받기" 버튼 없이 검증되면 자동 반영한다.
- 광고를 시작하기 전에 서버가 **남은 기회 1회를 예약**한다. 그래서 "끝까지 봤는데 한도 초과로 못 받는" 일이 없다(두 기기에서 마지막 1회를 동시에 쓰려 하면 한 쪽은 광고 시작 전에 "오늘 보상을 모두 받았어요"). 광고 없음·로드 실패면 예약을 돌려준다.
- 예약한 시도의 유효한 SSV는 늦게 와도(앱 종료·자정 이후·예약 만료 또는 로드 실패 신고 이후) 원래 약속한 보상량·유효기간 정책으로 1회 지급한다. 같은 광고 네트워크 거래 ID와 같은 예약 건은 한 번만 지급하며 클라이언트의 중간 종료 신고만으로 유효 SSV를 거절하지 않는다.
- 예약 만료·로드 실패로 반환된 기회를 재사용한 뒤 원래 광고의 유효 SSV가 도착하면 그 광고도 지급한다. 이 경우 원래 예약일의 지급 합계가 일시적으로 일일 한도를 넘을 수 있으나 이미 약속한 보상을 취소하거나 다음 날 보상에서 빼지 않는다. 지급량·광고 단위·정책 버전·예약일은 시작 시 고정하고 한도는 원래 예약일에 반영한다(06 AD_REWARD).
- 앱은 광고가 끝나면 지급 결과를 짧게 재조회하고, 확인 전에는 "포인트 지급을 확인하고 있어요"를 표시한다. 오래 확인되지 않으면 "다시 광고를 볼 필요 없어요" + `[지급 상태 확인]` `[문의]`.

### 5-3. 광고 노출 원칙

- 보상형 광고는 **사용자가 버튼을 눌러 선택했을 때만** 보여준다. 영상 중간·회차 사이에 강제 광고를 넣지 않는다 `[제안]`.
- 광고 버튼에는 받는 보상을 명확히 쓴다("광고 보고 10P 받기").

### 5-4. 추적 동의 · 개인정보

- iOS에서 맞춤형 광고를 위해 광고 식별자를 쓰려면 ATT 동의를 받는다. 거부해도 광고 보상 기능은 동작하게 한다(비맞춤 광고. 광고 공급량은 보장되지 않음).
- **ATT 동의에 보상을 주거나("동의하면 포인트") 동의를 기능 사용 조건으로 걸면 안 된다**(Apple 개인정보·ATT 지침).
- 광고 SDK가 수집하는 정보는 개인정보 처리방침과 스토어 개인정보 항목(App Privacy / Data safety)에 반영한다. SDK가 정책을 어기면 앱 개발자 책임이다(Google Play SDK 정책).
- **부적절한 광고 신고**: 광고가 있는 앱은 부적절하거나 연령에 맞지 않는 광고를 신고할 수단을 제공해야 한다(Apple 2.5.18). 광고 종료 후 화면과 고객센터 문의 유형에 "광고 신고"를 둔다(FN-WAL-15).

## 6. 충전 · 결제

### 6-1. 상품 · 가격

| 상품(시안) | 가격(시안) | 비고 |
|---|---|---|
| 100P | 1,100원 | `[시안]` |
| 300P | 3,300원 | `[시안]` |
| 600P | 6,600원 | `[시안]` |

- 앱에서 파는 포인트는 디지털 재화이므로 **iOS는 App Store 인앱결제, Android는 Google Play 결제**를 쓴다(App Store 3.1.1, Play 결제 정책). 외부 결제 링크·웹 결제 유도는 출시 범위에서 쓰지 않는다 `[제안]`.
- 화면의 가격은 **스토어에서 받아온 현지화 가격**을 그대로 표시한다(직접 하드코딩 금지).
- 상품은 **소모성(consumable)** 으로 등록한다. 큰 상품일수록 보너스(무상) 포인트를 더 주는 구성, 첫 구매 보너스는 `[제안]`.

### 6-2. 결제 처리

1. 서버가 현재 계정·상품 지급 내역에 귀속된 purchaseIntent를 먼저 생성한다. 앱은 이를 스토어 거래와 연결해 결제를 시작하고, 결제 성공 후 서버가 스토어의 확정 상태를 검증해 포인트를 지급한 다음 스토어 거래 완료 처리를 한다(06 §3-5).
2. 가족 승인·현금 결제 대기 등 스토어 `pending` 상태에는 지급하지 않는다. 앱이 중간에 꺼져도 다음 실행 때 미완료 거래를 같은 purchaseIntent로 복구한다. 로그아웃·다른 계정 로그인 후에도 결제 시작 계정 또는 그 최종 병합 계정에만 귀속한다.
3. 같은 스토어 거래 ID는 한 번만 지급한다. 서버 지급 완료와 스토어 완료 처리 상태를 따로 추적하여 지급 후 앱 종료로 완료 처리가 재시도되어도 중복 지급하지 않는다. 환불·취소가 먼저 확인된 거래를 나중에 성공 응답만 보고 지급하지 않는다. 탈퇴 계정의 후발 거래는 §1-4에 따른다.
4. 결제 상태 안내 문구:

| 상황 | 문구 |
|---|---|
| 사용자 취소 | "결제를 취소했어요. 포인트는 그대로예요." |
| 결제 확인 중 | "결제를 확인하고 있어요. 다시 결제하지 않아도 돼요." |
| 결제 완료·지급 대기 | "결제한 포인트를 확인하고 있어요." + "문의하기" |
| 지급 완료 | "{실제 지급한 충전 포인트}P를 충전했어요." 보너스가 있으면 실제 보너스 지급량도 구분해 표시. 현재 잔액은 최신 지갑 조회 결과로 표시 |
| 회차 열기 시트에서 왔을 때 | 지급 완료 후 같은 회차의 열기 시트로 복귀. 자동으로 열지 않음 |

### 6-3. 청약철회 · 환불 `[TBD — 약관 확정 필요]`

법적 근거(2026-10-12 확인, 부록 K1~K3): 전자상거래법 **제17조**는 원칙적으로 7일 이내 청약철회를 인정하고, 디지털콘텐츠는 제공이 시작되면 제한될 수 있되 **제한 사실을 미리 표시**하고 시험 사용(무료 회차 등)을 제공해야 한다. 나눌 수 있는 계약은 제공되지 않은 부분의 철회가 남는다. 표시·광고와 다르게 제공되면 공급일부터 3개월·안 날부터 30일 이내 철회할 수 있다. **제18조**는 디지털콘텐츠 철회 시 3영업일 이내 환급을 정한다.

- 기준안: **포인트 충전 계약**과 **회차 열기(이용)** 를 구분한다. 충전했다고 포인트 전체를 "이미 사용"으로 보아 환불을 막지 않는다.
  - 결제 후 7일 이내 · 사용하지 않은 유상 포인트 → 청약철회 가능.
  - 일부 사용 → 남은 유상 포인트 기준으로 처리(계산식·수수료 `[TBD]`). 다른 서비스의 "10% 수수료", "60% 사용 기준"을 근거 없이 가져오지 않는다.
  - 무상(보너스) 포인트는 환불 대상 아님. 보너스 포함 상품을 철회하면 그 보너스도 회수.
  - 오류·중복 결제·설명과 다른 제공은 단순 변심과 다른 경로로 처리한다.
- 실제 환불은 대부분 스토어(Apple/Google)가 처리한다. 스토어 환불 알림을 받으면 서버가 해당 유상 포인트를 회수하고(§4-6) 내역에 남긴다. 회사가 직접 받은 환불 요청은 처리 기록을 남긴다.
- **결제 전**에 충전 화면(WAL-01/05)과 유료 서비스 약관에 청약철회 가능 여부·조건·방법을 표시한다. 체크 하나로 법적 권리를 모두 포기시켰다고 주장하지 않는다.
- 아직 숫자를 정하지 않을 항목: 7일 이후 미사용 잔액 환급 조건, 부분 사용 보너스 회수, 작품 제공 중단 보상, 탈퇴 시 잔액 처리 → 법률 검토 후 확정 `[TBD]`(Q-09).

### 6-4. 미성년자

- 민법상 성년은 **19세**. 법정대리인 동의 없는 미성년자의 결제는 취소될 수 있으며(민법 제5조), 판매자는 이 취소 가능성을 고지해야 한다(전자상거래법 제13조). 약관·충전 화면에 안내하고, 취소 신청 절차(보호자 확인·필요한 최소 증빙)를 고객센터에 둔다.
- 모든 미성년 결제가 무조건 취소되는 것은 아니므로(법정 예외) 사례별로 검토한다.
- 스토어의 가족 결제·자녀 보호 설정을 따른다.

## 7. 찜

- 용어는 **"찜"** 으로 통일한다 `[확정: 2026-10-12]`(02 문서 §3-4). 버튼 "찜", 보관함 탭 "찜한 작품", 해제는 "찜 해제". 아이콘은 북마크 하나로 통일하고 "+"·"저장" 표기는 쓰지 않는다.
- 찜·해제는 즉시 반영하고 서버와 동기화. 실패하면 이전 상태로 되돌리고 "찜하지 못했어요. 다시 시도해 주세요."
- 찜 개수 제한 없음 `[제안]`. 정렬은 최근 찜한 순.
- 찜한 작품의 새 회차가 공개되면 알림 `[P1]`.

## 9. 알림

**P1 범위**다. P0에서는 필수 약관 동의만 받고 광고성·야간 푸시 선택 동의를 선취득하지 않는다. P1에서 앱 내 동의·철회, 기기별 권한·토큰 관리, 템플릿 분류와 발송 차단을 함께 구현한 뒤 활성화한다. 결제·보상 결과는 P0부터 앱의 거래 상태 조회로 확인한다.

| 종류 | 예 | 동의 |
|---|---|---|
| 서비스 알림 | 문의 답변, 결제·보상 처리 결과 | OS 알림 권한 + 앱 설정의 서비스 알림 켬 |
| 판단 필요 | 찜한 작품 새 회차 공개, 포인트 소멸 예정 | 사용자가 신청한 순수 안내인지, 시청·이용을 유도하는 광고성인지 **알림 문구(템플릿)별로** 판단한다 `[TBD]`. 광고성으로 판단되면 아래 광고성·야간 규칙을 적용 |
| 광고성 알림 | 이어보기 리마인드, 이벤트, 보상 안내 | OS 권한 + **앱 내 광고성 정보 수신 동의**(별도, 기본 꺼짐). 제목에 "(광고)" 표기, 발신자·수신 거부 방법 안내. 철회 후 발송 금지 |
| 야간 광고성 알림 | 21:00~08:00 발송 | **별도 사전 동의** 필요(정보통신망법 제50조). 동의가 없으면 이 시간대 발송을 서버에서 막는다 |

- 저장하는 동의는 세 가지로 따로: **OS 알림 권한 / 광고성 정보 수신 동의 / 야간 광고성 수신 동의**. Apple 4.5.4도 홍보 푸시는 명시적 선택과 앱 안 해제 수단을 요구한다. 동의·철회는 덮어쓰지 않고 이력으로 남긴다(06 CONSENT_EVENT) — 발송 근거를 증명해야 한다.
- 거래 안내(결제·보상 결과) 알림 제목에 프로모션을 섞어 광고성 알림 의무를 피하지 않는다.
- OS 알림 권한 요청 전에 **앱 안내 화면**으로 이유를 먼저 설명한다(SYS-02). 첫 실행 즉시가 아니라 의미 있는 시점(첫 찜, 3화 시청 후)에 요청 `[제안]`.
- 광고성 정보 수신 동의자에게는 동의 사실을 주기적으로 다시 알린다(정보통신망법 시행령의 수신 동의 확인 주기 — 세부 주기는 법무 확인 `[TBD]`).
- 알림을 눌러도 포인트 지급·회차 열기·결제가 자동으로 일어나지 않는다.
- 잠금화면 보상 카드(Live Activities)는 플랫폼 정책상 광고·프로모션 용도로 부적합해 보류. 대안은 일반 알림(`_docs/AI_DRAMA_잠금화면_기능기획.md`).

## 12. 공통 문구 규칙

- 존댓말 해요체. 짧게, 결과 중심으로("10P로 9화 보기", "광고 보고 10P 받기").
- 실패 문구는 **무슨 일이 있었는지 + 다음 행동**("영상을 불러오지 못했어요. 다시 시도해 주세요.").
- 돈·포인트 관련 문구에는 숫자를 정확히 쓴다. "무료", "획득 완료" 등 실제와 다를 수 있는 표현을 쓰지 않는다.
- 현재 시안의 "체험", "샘플 화면", "실제 결제 없음" 문구는 실서비스 연동 시 모두 제거한다.
