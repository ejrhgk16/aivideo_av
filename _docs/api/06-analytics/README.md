# Analytics API

> 상태: 제안. 아직 구현되지 않았다. 관리자 지표 정의서 초안 v0.1(2026-11-25)의 확정 결정을 기준으로 한 계약 초안이다. 정의서는 저장소 밖에서 관리하며, 이 계약에 쓰는 결정은 아래 요약과 각 문서 본문에 모두 옮겼다.

관리자 대시보드 지표를 실제 수집 데이터로 만들기 위한 앱 이벤트 수집 API를 관리한다. 관리자 사이트는 서버가 매일 만드는 일별 집계 테이블을 DB에서 직접 읽으므로 이 도메인에는 지표 조회 API가 없다.

- [분석 이벤트 수집](./events.md): 비로그인 포함 빼꼼 노출·본편 재생 이벤트 묶음 전송, 재생 세션 ID 발급, 검증·한도·보관 규칙
- [데이터 모델 제안](./data-model-proposal.md): 원본·일별 집계 테이블 정의의 검토용 사본

## 지표 정의 요약

날짜는 한국 시간(KST) 하루 기준이다. 대시보드 기간(최근 7/28/90일과 바로 앞 같은 길이 기간)은 어제(KST)까지다. 오늘 집계는 다음 날 만들어진다. `추천`은 정의서의 [미정] 항목에 적힌 추천안을 따른 값이다.

| 지표 | 단위 | 정의 | 원천 이벤트 |
| --- | --- | --- | --- |
| 노출수 | 작품 | 빼꼼에서 작품의 쇼츠 카드가 화면에 뜬 횟수. 같은 기기·작품은 마지막으로 센 노출 뒤 30분 안의 노출을 세지 않는다(추천) | `feed_impression` |
| 조회수 | 회차, 작품은 합계 | 본편 회차 재생이 시작된 횟수(유튜브 기준). 빼꼼 쇼츠·미리보기 재생은 넣지 않는다 | `playback_start` |
| 참여 조회 | 회차 | 실제 재생 시간이 3초 이상인 조회. 보조 지표(추천) | `watchedMs` |
| 조회율 | 작품 | 빼꼼 노출 뒤 같은 기기에서 24시간 안에 그 작품 본편을 재생한 비율 | 노출 + 조회 |
| 시청 시간·평균 시청 비율 | 회차 | 실제 재생 시간의 합(조회 1건당 회차 길이 상한) ÷ (조회수 × 회차 길이). 회차 길이는 조회마다 재생한 영상의 길이다 | `watchedMs` |
| 완주율·이탈률 | 회차 | 회차의 90% 지점까지 도달한 조회의 비율(추천). 이탈률은 1 − 완주율 | `maxReachedMs` |
| 구간 이탈 곡선·도달률 | 회차 | 0%, 5%, …, 100%의 21개 점마다 그 지점까지 도달한 조회의 비율. 도달률은 25/50/75/100% 점 | `maxReachedMs` |

회차(캠페인) 화면에는 노출수와 조회율이 없다. 노출이 작품 단위이기 때문이다. 앱의 기존 시청 완료 표시(2/3 기준, [시청기록 저장](../04-playback/watch-progress.md))는 바꾸지 않고 완주(90%)와 따로 둔다.
