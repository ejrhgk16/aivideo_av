# 잠금화면 보상 안내 기능 기획

추가일: 2026-09-11  
대상: AI DRAMA iPhone·Android 앱  
상태: 추가 기획. 앱과 공개 웹 시안에는 아직 구현하지 않음.

## 사용자가 원하는 경험

앱을 사용하다가 휴대폰을 잠그고 화면을 다시 켰을 때, 잠금화면에서 보상 안내 카드와 남은 시간을 확인한다. 카드를 누르면 앱의 포인트 화면으로 돌아간다.

참고 화면은 사용자가 제공한 NetShort의 iPhone 실시간 현황 화면이다. 화면 아래의 “실시간 현황을 허용하겠습니까?” 안내는 iOS가 관리한다. 이 시스템 안내의 문구와 표시 시점을 앱에서 그대로 만들거나 고정하지 않는다.

## 요청안과 적용 판단

| 구분 | 내용 |
| --- | --- |
| 요청안 | 잠금화면 보상 카드, 카운트다운, 보상 확인 버튼 |
| iPhone에서 보이는 기능 이름 | 실시간 현황(Live Activities) |
| 표시 원리 | 이미 시작한 현황을 운영체제가 잠금화면에 표시한다. 화면을 켤 때마다 새로 뜨는 앱 팝업으로 구현하지 않는다. |
| 현재 판단 | 보상 수령을 유도하는 카운트다운은 광고·프로모션 목적이어서, Apple Live Activities와 Android Live Updates의 권장 용도와 맞지 않는다. 원안을 출시 확정 기능으로 표시하지 않는다. |
| 함께 검토할 대안 | 명시적으로 동의한 사용자에게 자체 포인트 보상 관련 일반 알림을 보내고 앱의 포인트 화면으로 연결한다. 자세한 카운트다운은 앱 안에 둔다. |
| 보상 정책 | 지급량, 지급 조건, 발송 횟수, 유효기간은 미정. 레퍼런스의 약 9시간 타이머나 표시 금액을 서비스 정책으로 채택하지 않는다. |

## 카드 구성

| 위치 | 표시할 내용 |
| --- | --- |
| 앱 표시 | 최종 확정 전까지 AI DRAMA 이름과 앱 아이콘 |
| 제목 | 예: “확인할 수 있는 보상이 있어요” |
| 설명 | 예: “앱에서 보상 조건과 남은 시간을 확인해 주세요.” |
| 남은 시간 | 요청안에 포함하되, 실제 종료 시각이 정해진 보상에만 표시한다. 일반 알림 대안에서는 상세 타이머를 앱 내부에서 제공한다. |
| 누르는 곳 | “보상 확인하기”. 실제로 즉시 지급하지 않으므로 “획득 완료”라고 쓰지 않는다. |
| 이동 화면 | 잠금 해제가 필요한 경우 해제 후, 포인트 화면의 해당 보상 위치를 연다. |

카드의 크기, 위치, 버튼 모양은 운영체제와 기기 설정을 따른다. 원본의 큰 그라데이션 버튼, 시스템 권한 문구, Dynamic Island 형태가 모든 기기에서 똑같이 보인다고 보장하지 않는다.

## 일반 알림 대안의 이용 흐름

1. 포인트 화면에서 사용자가 “보상 알림 받기”를 직접 켠다. 기본 상태는 꺼짐으로 제안한다.
2. 보상·혜택 알림 수신에 대한 앱 내 동의를 받고, 별도로 운영체제의 알림 권한을 확인한다.
3. 실제 대상 보상이 생겼거나 정해진 알림 시점이 되었을 때 알림을 보낸다. 휴대폰 화면을 켜는 행위는 발송 조건으로 사용하지 않는다.
4. 운영체제의 잠금화면 표시 설정이 허용하면 사용자가 잠금화면에서 알림을 확인할 수 있다.
5. 알림을 누르면 앱에서 현재 보상 상태를 다시 확인한다.
6. 필요한 광고 시청 등 보상 조건은 앱 안에서 수행한다. 수령 확인 후에만 보상을 지급한다.

## 상태와 예외

| 상황 | 동작 |
| --- | --- |
| 앱 내 수신 동의 또는 OS 알림 권한 없음 | 알림을 보내지 않는다. 앱 내부의 포인트 이용은 가능하다. |
| 집중 모드·알림 미리보기 숨김·잠금화면 알림 꺼짐 | 즉시 표시나 상세 내용 표시를 보장하지 않는다. 해당 보상은 앱에서 확인한다. |
| 같은 보상 안내를 이미 보냄 | 보상 식별자를 기준으로 중복 발송하지 않는다. |
| 사용자가 알림 또는 현황을 닫음 | 단순히 화면을 켰다는 이유로 다시 게시하지 않는다. |
| 앱 내 알림 설정을 끔 | 이후 발송을 중단하고 이 기능의 예약 알림을 취소한다. |
| 보상이 만료됨 | 앱에서 “보상 기간이 끝났어요”를 표시한다. 남은 알림은 가능한 경우 취소·갱신한다. |
| 이미 받은 보상 | “이미 받은 보상이에요”와 이용 내역을 안내하고 다시 지급하지 않는다. |
| 확인 중 네트워크 오류 | 지급 완료로 표시하지 않고 다시 확인하도록 안내한다. |
| 알림을 누름 | 자동 포인트 지급, 유료 회차 열기, 포인트 차감, 광고 자동 재생을 하지 않는다. |
| 다른 계정에서 연 알림 | 현재 계정의 보상 대상 여부를 다시 확인하며 타인의 보상을 지급하지 않는다. |

## iPhone 적용 조건

- 실시간 현황은 ActivityKit과 전용 잠금화면 UI를 사용한다. 일반적인 앱 내 시작은 앱이 화면에 열린 상태에서 요청한다. 별도 서버 푸시 시작 등은 지원 버전과 구현 범위를 추가로 검토한다.
- 사용자가 실시간 현황을 꺼두면 표시할 수 없다. 지원 기기에서는 Dynamic Island에도 나타날 수 있다.
- Apple은 Live Activities에서 광고·프로모션을 표시하지 않도록 안내한다. 단순히 “보상 현황”이라고 이름만 바꾸어 이 제약을 피하지 않는다.
- 실시간 현황은 활성 상태가 최대 8시간이다. 종료 후 잠금화면에는 최대 4시간 더 남을 수 있다. 레퍼런스의 약 9시간 카운트다운이 그대로 가능한 것으로 기획하지 않는다.
- 일반 홍보 알림은 앱 UI에서 명시적인 수신 동의를 받고, 앱 안에 해제 방법을 제공한다. iOS의 알림 허용만으로 보상·혜택 알림 동의를 대신하지 않는다.

## Android 적용 조건

- 일반 알림을 기본 대안으로 검토한다. Android 13 이상에서는 일반 알림 권한 허용이 필요하며 알림 채널과 잠금화면 설정을 따른다.
- Live Updates는 진행 중이고 사용자가 시작했으며 지속적인 확인이 필요한 활동을 위한 기능이다. 광고·프로모션은 부적절한 용도로 명시된다.
- Live Updates는 지원 OS·기기에서 표준 알림 형식을 사용하며, 제조사별 추가 조건이 있을 수 있다. iPhone 원본 카드와 동일한 디자인을 약속하지 않는다.
- 이 기능의 알림은 앱 자체 보상 안내로 한정한다. 다른 앱이나 외부 광고를 시스템 알림에 노출하지 않는다.
- 알림을 유지하려는 목적만으로 실제 작업이 없는 상시 백그라운드 서비스를 만들지 않는다.

## 개발 시 나눌 작업

- 앱 화면: 포인트 화면의 보상 안내, 남은 시간, 알림 설정, 만료·이미 수령 상태.
- 알림 연결: 사용자 수신 동의, OS 권한, 알림 채널, 누르면 포인트 화면을 여는 연결.
- 서버: 실제 보상 조건과 종료 시각 관리, 발송 대상 확인, 중복 발송·중복 지급 방지, 알림 수신 해제 반영.
- 기기 확인: iPhone·Android에서 앱 실행 중/백그라운드/종료 상태의 알림 열기와 잠금 해제 후 이동을 확인한다. 화면을 켜는 순간의 노출을 성공 기준으로 삼지 않는다.

## 확인 기준

- 앱 내 보상 알림 동의와 OS 권한을 구분해 저장한다.
- 동의하지 않은 사용자에게 보상 알림이 가지 않는다.
- 알림을 누르면 해당 보상을 앱에서 확인할 수 있다.
- 미리보기 숨김·알림 거부·수신 해제·만료·중복 수령 상황을 처리한다.
- 잠금화면 카드나 버튼을 누르는 것만으로 포인트가 바뀌지 않는다.
- 실시간 보상 카드 원안과 일반 알림 대안의 구현 여부를 각각 표시한다.
