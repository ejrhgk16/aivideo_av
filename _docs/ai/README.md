# AI 작업 규칙 (Claude × GPT)

작성: 2026-10-21 · 리드: Claude · 결정: 기획 담당(마케터)

## 원칙

1. **개발자 코드가 기준이다.** GitHub `dev`(개발자 작업)를 기준 코드로 삼는다.
2. **개발자 브랜치는 건드리지 않는다.** AI(Claude·GPT)와 이 PC는 GitHub `dev`·`main`에 push하지 않는다. 이 PC의 `.git/hooks/pre-push`가 두 브랜치로의 push를 막는다(해제하려면 그 파일을 지운다).
3. **AI 작업은 `ai/*` 브랜치에서만 한다.**
   - `ai/dev`: 개발자 `dev`에서 갈라진 AI 통합 브랜치. 기획서(`_docs/spec/`)와 AI 작업 결과가 쌓인다.
   - 기능별 작업은 `ai/dev`에서 `ai/<작업명>`으로 갈라 진행하고, 검수 후 `ai/dev`에 합친다.
   - 개발자 `dev`로의 반영은 **개발자가 직접 검토하고 선택**한다(Pull Request 또는 cherry-pick).
4. **최신 개발자 코드를 먼저 받는다.** 작업을 계획하기 전과 `ai/dev`에 합치기 전에 `git fetch origin`으로 개발자 `dev`를 확인하고, 필요하면 `ai/dev`를 개발자 `dev` 위로 맞춘다.
5. **개발자 규칙을 따른다.** 루트 `AGENTS.md`의 테스트 위치(`front/tests/`, `back/test/unit/`), API 문서(`_docs/api/`) 갱신, `_docs/ARCHITECTURE.md` 갱신 규칙을 지킨다. 단, Harness의 "`dev`에서만 작업" 규칙은 위 2·3번 결정에 따라 AI에게는 적용하지 않는다. `web-prototype/`은 수정하지 않는다.
6. **개발자 파일 수정은 최소한으로.** 기획 문서는 AI 전용 위치(`_docs/spec/`, `_docs/ai/`)에 새 파일로 둔다. 앱·서버 코드를 바꿀 때는 개발자 구조·이름 규칙을 따르고, 큰 구조 변경은 개발자와 합의한다.

## 이전 AI 작업 (참고용 보관)

2026-10-20 진행한 0단계·1단계 1a는 개발자 최신 코드를 받기 전 기준으로 만들어져 개발자 구조(TypeORM 등)와 겹친다. 로컬 브랜치 `ai/phase0-1-backup`에 보관했으며 `dev`에 합치지 않는다. 다시 쓸 만한 것:

- 앱: 찜 용어 통일, 회차 열기 시트 출시 디자인(광고·충전 후 같은 회차로 복귀), 첫 실행 동의·생년월일·14세 미만 충전/광고 차단, 체험/출시 경제 분리, `expo-video` 실제 플레이어(만료 재발급·화면 꺼짐 방지), 로딩·오류·빈 목록 상태, 목록 요청 격리.
- 서버(개발자에게 제안할 설계): 공통 오류 형식 `{code, message, retryable, requestId, details}`, 재생 거부 사유 코드, 공개 조건 DB 제약, DB 설치 없는 로컬 실행(PGlite), 개발용 픽스처 표시(`DEV-FIXTURE`).
